# cgv-data Data Contract

Status: normative  
Canonical architecture: `Biblia-LBF/docs/architecture/CGV_DATA_ARCHITECTURE.md`

## Purpose

`cgv-data` is the distribution repository for stable CGV content. It contains versioned, validated artifacts consumed by applications and tools. For LBF, it is the published source of truth, not the editable project source.

## Owned data

- Published Bible datasets.
- Published LBF text and alignment generated from `Biblia-LBF`.
- Published songs, courses, morphology, media metadata, and other approved datasets.
- Dataset manifests, catalogs, checksums, schemas, licenses, and immutable versions.
- A small current-version pointer for consumers that deliberately follow the newest release.

## Required invariants

- Every dataset has a stable ID, schema version, semantic version, and manifest.
- Released version directories are immutable.
- A manifest records provenance, licenses, included scope, file checksums, and build information.
- Generated datasets identify their exact source repository and commit SHA.
- LBF text and LBF alignment are published atomically under the same version.
- Every file in a release is declared by its manifest.
- `current.json` points only to a complete, validated version.
- Consumer-facing paths and formats change only through an explicit schema or major-version migration.

## Allowed writes

Writes may originate from:

- reviewed publisher pull requests generated by an owning source repository;
- reviewed imports for datasets that do not yet have an automated publisher;
- explicit metadata or schema maintenance.

For LBF, normal publication must originate from the `Biblia-LBF` exporter. Manual editing of generated LBF text or alignment is prohibited.

## Consumer contract

Consumers may:

- pin an immutable dataset version;
- deliberately resolve `current.json`;
- validate checksums and schema versions;
- cache artifacts without modifying their meaning.

Consumers must not require undocumented files, infer versions from Git timestamps, or write changes back into this repository.

## Prohibited content and behavior

- Draft translations or draft alignments.
- Translator comments, approval queues, editor state, or user progress.
- Alignment generation or repair scripts.
- App-specific fixtures mixed into published datasets.
- Undeclared files inside versioned releases.
- Direct overwrites of an existing released version.
- Licensed content without distribution permission.

## Pull-request gate

CI must verify schemas, checksums, manifest completeness, provenance, licenses, immutable-version protection, and atomic LBF text/alignment publication.
